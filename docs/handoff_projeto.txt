================================================================================
1. O QUE É ESTE JOGO
================================================================================

Protótipo de duelo 2D local (PvP ou treino) no género "ranged fighter":
dois lutadores em metades opostas de uma arena atiram projéteis, usam skills
e movimentação de plataforma (pulo duplo, dash, wall jump, queda rápida no ar).

Cada personagem tem um kit distinto (tiro carregado, granadas, míssil
teleguiado, escudo, etc.), mas partilham a mesma base técnica (Player) e a
mesma cena física (main.tscn). O script do lutador é trocado em runtime.

Objetivo de combate: reduzir o HP do adversário (100 por defeito). No modo Vs,
vence quem ganhar 3 rounds (KO por HP ou timeout de 60 s por round).

================================================================================
2. MODOS DE JOGO (RunConfig.mode)
================================================================================

VS_PLAYER
  - Dois humanos (teclado+mouse vs controle, ou ambos com esquemas configuráveis).
  - Menu: ui/vs_character_menu.tscn — escolha de classe P1/P2, palco, input.
  - Rounds: 60 s, primeiro a 3 vitórias; banner entre rounds; menu fim de partida.

TRAINING
  - P1 humano; P2 é boneco à direita (script pistoleiro por defeito no assign).
  - Menu: ui/training_menu.tscn — classe P1, palco, input, toggle tiro automático
    do boneco (intervalo RunConfig.training_dummy_interval, default 3 s).
  - Atalho ao abrir treino: Esqueleto + controle 0 + boneco sem tiro auto.

Fluxo de menus:
  start_game.tscn → menu.tscn → Vs ou Treino → levels/duel/main.tscn (Game)

3. PERSONAGENS (Player.CharacterKind)
================================================================================

ID  Nome              Script                         Papel
--  ----------------  -----------------------------  ---------------------------
0   Pistoleiro        pistoleiro_player.gd           Tiro reto, ricochete, cadeia
                                                      3 bocas, granada, escudo (4)
1   Arqueiro          arqueiro_player.gd             Flecha balística, split, espinhos,
                                                      escudo com reflect + cura
2   Mago              mago_player.gd                 Míssil teleguiado, gelo, levitação,
                                                      orbe gravitacional
3   Esqueleto         esqueleto_player.gd            BASELINE DE DESIGN — tiro reto
                                                      carregado, feixe (F/X), buff velocidade
                                                      tiro (G/Y), dash por Shift/B
4   Ongma Epilef      ongma_epilef_player.gd         Laboratório: extends EsqueletoPlayer;
                                                      overrides mínimos para testar mecânicas

Política de design (documentada em docs/esqueleto_personagem_base.md):
  - Novos personagens partem numericamente/conceptualmente do Esqueleto.
  - Código comum → player.gd; kit esqueleto → esqueleto_player.gd; testes → ongma.
  - Família EsqueletoPlayer: Game trata flecha sem gravidade e HUD de buff com
    "owner_player is EsqueletoPlayer" (inclui Ongma).

Resumo de kits (detalhe em docs/personagens/*.md):

  PISTOLEIRO
    - Tiro carregado; cadeia alterna MuzzleTop / MuzzleBottom / duplo tiro.
    - G: buff 3 ataques especiais; F: granada instantânea ou detonar.
    - Flecha: g=0, 1 ricochete por defeito no spawn.

  ARQUEIRO
    - Tiro carregado com gravidade (1200) no voo.
    - F: buff 3 tiros espinho; G: split ou leque de 5 com combo.
    - Escudo: 3 cargas, reflect +6 HP.

  MAGO
    - "Tiro": míssil teleguiado (360–520 px/s, carga 0,85 s).
    - F: gelo; C: levitar; G segurar: orbe.

  ESQUELETO / ONGMA
    - Tiro carregado; cooldown mínimo 1 s após disparo.
    - F/X: Feixe (projétil grande carregado, dano 36, escala variável).
    - G/Y: Buff ~4 s — tiros carregados ×2 velocidade (CD ~10 s).
    - Dash: tecla dedicada (Shift / B), não duplo toque.
    - Flecha: g=0, 0 ricochetes.

================================================================================
4. ARQUITETURA DE CÓDIGO
================================================================================

4.1 Padrão Template Method (Player + subclasses)
  - player.gd (class_name Player, extends CharacterBody2D):
      movimento, gravidade, dash, pulo, wall jump, sprint pós-dash, mira
      (mouse ou stick direito), recoil, vida, sinais de combate, limites de arena.
  - Hooks vazios/overridable: _process_combat, _get_dash_stats (unificado na base),
      uses_dash_action_button, _preview_gravity_for_shot, is_*(), etc.
  - Subclasses só implementam o que difere.

4.2 Game como coordenador (levels/duel/game.gd)
  - Conecta sinais shoot_requested / shots_requested / grenade / mage / etc.
  - _spawn_one_arrow: regras de gravidade, ricochete, homing, carrier arqueiro.
  - _ensure_input_map: monta InputMap por RunConfig (teclado vs gamepad por jogador).
  - Modo Vs: timer, placar, respawn entre rounds, KO, pits de palco.
  - _apply_stage_from_run_config: Normal / Tiered Abyss / Old Factory.

4.3 RunConfig (autoload)
  - Persiste escolhas da sessão: mode, stage, p1/p2_character, input schemes,
    joy devices, flags de treino.
  - Helpers: resolve_exclusive_keyboard_mouse, clear_shoot_mouse_bindings_for_menu,
    get_shoot_hint_token_for_player ("mouse" ou "RB").

4.4 Cena de duelo (levels/duel/main.tscn)
  - LeftPlayer / RightPlayer: mesmo CharacterBody2D 40×90, script trocado via
    Game._assign_player_script(set_script) em _enter_tree.
  - ArenaVariantRoot: instancia palcos variantes.
  - UI: HP, especiais, hints de skills, VsHud (timer, placar, nomes).

4.5 Projéteis (projectiles/<nome>/)
  - Cada um: .tscn + .gd na mesma pasta (snake_case).
  - Arrow (CharacterBody2D): gravidade manual, ricochete, dano, knockback.
  - HomingMissile extends Arrow; Grenade, GravityOrb, ArcherSpike, IceMissile,
    IceField, Fireball, Explosion conforme personagens.

4.6 UI
  - ui/menu_theme.gd (MenuThemeUtil): estilos, fill_class_option, fill_stage_option,
    vs_character_name/accent (0..4).
  - Pausa: pause_menu_controller.gd, training_pause_menu_controller.gd.
  - Fim de partida Vs: vs_match_end_menu.gd.

4.7 Câmera (levels/duel/camera/)
  - Camera2D fixa (960, 432); efeitos só via CameraSystem (grupo "camera_system").
  - v1: shake + hit stop + flash no Feixe do Esqueleto (presets .tres).
  - Integração centralizada em game.gd; Arrow.set_shot_flags para tag esqueleto_feixe.
  - Ver docs/sistema_camera.md e docs/camera_implementacao_v1.txt.

================================================================================
5. INPUT E CONTROLES
================================================================================

Montagem em Game._ensure_input_map() ao entrar no duelo.

Regra Vs: apenas UM jogador pode usar KEYBOARD_MOUSE; o outro GAMEPAD
(RunConfig.resolve_exclusive_keyboard_mouse).

Teclado+mouse (layout partilhado P1 ou P2 quando ambos usam KB+mouse no treino):
  A/D mover | Espaço pulo | W/S hover (mago flutuação) | Q escudo
  Mouse: mira + tiro (botão esquerdo em p*_shoot)
  Shift: p*_dash (Esqueleto/Ongma); duplo A/D dash nos outros
  F granada/feixe/gelo/espinhos | G especial | C levitar (mago)
  S / p*_down no ar: ground pound (queda rápida, vy=2000)

Controle (por jogador, device RunConfig.p1_joy_device / p2_joy_device):
  Stick esq + D-pad: mover; duplo toque frente/trás = dash (não-esqueleto)
  Stick dir: mira (aim_* com deadzone/smoothing em Player)
  A pulo | B dash (Esqueleto) | RB tiro | LB escudo | X feixe/gelo/granada
  Y especial/buff | L3 espinhos arqueiro | R3 levitar mago
  RT/LT: hover up/down na flutuação

Esqueleto/Ongma: uses_dash_action_button() = true → dash só por p*_dash.
Outros: uses_dash_action_button() = false → dash por duplo toque horizontal;
  input vertical durante a janela cancela o par.

Menus: RunConfig.clear_shoot_mouse_bindings_for_menu() para cliques funcionarem.

Dicas no HUD: Game._skill_hint_lines() por personagem e esquema de input.

6. MOVIMENTO E COMBATE (Player — valores base actuais)
================================================================================

Referência completa: docs/sistemas_core_arena_e_movimento.md
Stats Esqueleto: docs/esqueleto_personagem_base.md

Movimento horizontal: move_speed 260 px/s
Gravidade: 1800 px/s² | Pulo: jump_speed 700 | max_jumps 2

Dash (UNIFICADO na base Player._get_dash_stats para todos):
  speed 620 | duration 0,2 s | cooldown 0,1 s | gravity_scale 0
  - No ar: sem aceleração gravitacional; corta vy>0 durante dash (queda residual).
  - limit_air_dash_to_one: 1 dash aéreo por sequência até tocar chão.
  - dash_min_gap_seconds 0,06: anti-spam encadeado.
  - Pulo durante dash: impulso diagonal composto (dash_jump_* exports).

Sprint:
  - sprint_mechanic_enabled = false (corrida por segurar frente desligada).
  - post_dash_sprint_enabled = true: após dash, janela 0,18 s mantendo frente
    activa sprint (×1,55) + indicador visual opcional.

Wall jump: detecta parede, impulso diagonal, 1× por voo, flash visual.

Ground pound: p*_down no ar → velocity.y = 2000, zera vx.

Mira: ±85°; mouse ou stick direito com deadzone/suavização (gamepad).

Recoil: recoil_normal 170, decay 2400; carry knockback horizontal separado.

Arena: _enforce_arena_half — padding 36 px; metade do ecrã por player_id;
  half_gap_extra por palco (0 / 52 / 88).

Congelamento (freeze_for), stun por knockback, escudo hold (subclasses).

7. PALCOS / STAGES (RunConfig.stage)
================================================================================

Documentação detalhada: docs/staging_stages.txt

NORMAL
  Chão contínuo layer 1; spawns ~(210,672) e ~(1710,672).

TIERED_ABYSS ("Patamares + abismo")
  Plataformas one-way layer 16 (ArenaPlatforms); fossos laterais;
  queda no pit: 30 HP, respawn no spawn do palco, CD 0,85 s.

OLD_FACTORY ("Fábrica antiga")
  Duas ilhas de chão + vale central; pit partilhado; half_gap_extra maior.

Projéteis: mask não inclui layer 16 → atravessam plataformas de palco;
  jogadores collision_mask 19 (1+2+16).

8. REGRAS DE SPAWN DE PROJÉTEIS (Game._spawn_one_arrow)
================================================================================

  - Mago → HomingMissile (g=0 forçado no setup).
  - Pistoleiro ou EsqueletoPlayer → g=0 na flecha.
  - Arqueiro → gravidade arrow.gravity_accel (1200).
  - Ricochetes default: pistoleiro b=1, resto b=0 (salvo override no payload).
  - ArcherSpike, Grenade, GravityOrb, IceMissile: sinais dedicados.

11. COMO EXECUTAR E DESENVOLVER
================================================================================

1. Godot 4.x estável → Import → pasta com project.godot → F5.
2. Vs: menu → Vs Player → classes, palco, input → Começar.
3. Treino: menu → Treinamento → opções P1 → Começar.
4. Alterar personagem default: RunConfig em menus ou exports na cena.
5. Balanceamento Esqueleto: editar exports em esqueleto_player.gd + actualizar
   docs/esqueleto_personagem_base.md na mesma PR.
6. Nova mecânica global: preferir hooks em player.gd; kit esqueleto só se for
   do arquétipo; ongma_epilef para prototipar antes de subir.

Testes manuais sugeridos:
  - Vs com cada par de classes × palco Normal + Tiered + Factory
  - Teclado+mouse P1 + gamepad P2
  - Respawn Vs, pit damage, timeout de round
  - Ongma Epilef = paridade Esqueleto até haver overrides

12. ESTADO ACTUAL E NOTAS PARA AGENTES
================================================================================

  - Protótipo jogável; balanceamento em evolução contínua.
  - Dash stats foram UNIFICADOS na classe Player (620/0,2/0,1/g0) — subclasses
    antigas que sobrescreviam _get_dash_stats podem já não fazê-lo; confirmar
    no grep antes de assumir diferenças por personagem.
  - Esqueleto deixou de ter skill "triplo 3 flechas"; actual = buff velocidade
    tiro + feixe. HUD e docs antigos podem mencionar triplo — código em
    esqueleto_player.gd é autoritativo.
  - README.md menciona Area2D para flecha; código usa CharacterBody2D (arrow.gd).
  - ground_pound (_start_ground_pound_dash) é WIP/experimental (vy fixo 2000).
  - Câmera v1: só Feixe Esqueleto; KO/hit genérico ainda sem feedback — ver
    docs/camera_implementacao_v1.txt.
  - Vs: 3 rounds to win, 60 s/round; training dummy atira se training_dummy_shoot.
  - Export preset presente (export_presets.cfg) para builds futuras.

Para trabalhar numa feature:
  1. Ler player.gd + subclass alvo + game.gd (spawn/input).
  2. Comparar com esqueleto_personagem_base.md se afectar pacing.
  3. Actualizar doc correspondente em docs/ no mesmo change set.
